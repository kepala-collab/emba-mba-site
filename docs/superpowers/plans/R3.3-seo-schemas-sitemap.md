# R3.3 — SEO, schemas and sitemap

## Goal

Stop the sitemap from drifting: derive it from `EN_ROUTES` and `LOCALE_PAIRS` instead of ten hand-maintained buckets, and prove the derivation with a unit test. Bring the Malay and Chinese pages to schema parity with English, and make the OpenGraph image render Chinese titles.

## Model and role

Sonnet, single technical executor. Schema `name`/`description` text fields come from the already-merged Release 2 copy constants — no new copy is authored, so no language reviewer is needed. If a schema field has no existing constant, use the page's own merged heading rather than writing new prose.

## Inputs — read these first, in full

- `docs/superpowers/specs/2026-09-03-site-quality-programme-design.md` (section R3.3)
- `src/app/sitemap.ts` (94 lines — ten hand-maintained buckets at 12–52, `REVIEW_DATES` at 5–10, `alternatesFor` at 54)
- `src/lib/locale-routes.ts` (82 lines — `EN_ROUTES` at 7–45, `LOCALE_PAIRS` at 47, `languageAlternates` at 57)
- `src/lib/seo.ts` — `withSeo`, the stable `@id` values at lines 8–14, `breadcrumbSchema` at 79–90
- `src/app/opengraph-image/route.tsx` — `fontFamily: "Arial, sans-serif"` at line 20, `force-static` at line 6
- `src/app/(en)/intakes/page.tsx`, `(en)/about/page.tsx`, `(en)/faculty/page.tsx` — the English schema blocks the Malay and Chinese pages must match

## Constraints

- **Facts never change.** Schema text fields are interpolated from `content.ts`, `content-ms.ts`, `content-zh.ts` or the page's merged headings. Never retype a fact into JSON-LD.
- **Never add a claim to structured data that is not visible on the page.** `SEO-CONTENT-GOVERNANCE.md`, Evidence standard: no ratings, outcomes or credentials in schema unless visible and supported.
- **The noindex set must stay out of the sitemap.** Those routes are `/corporate-training`, `/online-executive-mba`, `/programmes/shift-hr`, `/lp/google`, `/lp/meta`, `/unsubscribed` (all three locales) and the `/` root stub. Today's buckets already exclude them; the derived version must too, and the test must prove it.
- **`EN_ROUTES` has 37 entries and there are five insight articles.** Derive; never hand-copy.
- **Branch and release action.** Create `feat/r3-3-seo-schemas-sitemap` from `codex/hostinger-deployment`. Pushing the feature branch for CI is allowed. Merging into `codex/hostinger-deployment` and pushing that branch **is the deployment**; only after the section-6 gate is green.
- Hostinger configuration is out of scope. **IndexNow submission is a post-deployment step**, not part of this brief's acceptance — see Out of scope.
- Run this brief **after** R2.1, R2.2 and R2.3 have merged, so schema text fields quote final copy.

## Steps

1. `git checkout codex/hostinger-deployment && git checkout -b feat/r3-3-seo-schemas-sitemap`.
2. **Snapshot the current sitemap.** `npm run build && npm start`, then `curl -s http://localhost:3000/sitemap.xml > /tmp/sitemap-before.xml`. Extract the sorted URL list. This is your regression oracle: the derived sitemap must be a superset-or-equal of the current one on indexable routes, with no noindex route added.
3. **Write the failing test first.** Create `src/app/__tests__/sitemap.test.ts`:
   - Define `NOINDEX_ROUTES` once, listing the seven English paths above.
   - For every `EN_ROUTES` entry not in `NOINDEX_ROUTES`, assert the sitemap contains exactly **one** entry for the English URL, one for its `zh` pair and one for its `ms` pair — `filter(e => e.url === expected).length === 1`.
   - Assert **no** sitemap entry matches any noindex route in any locale, and none matches the `/` root stub.
   - Assert every entry has `alternates.languages` with `en`, `zh-Hans`, `ms` and `x-default` keys.
   - Assert `priority` is one of the declared route-class values and `changeFrequency` is `weekly` or `monthly`.
   - Assert total entry count equals `3 * (EN_ROUTES.length - NOINDEX_ROUTES.length)`.
4. `npm test` — red, because the hand-maintained buckets do not cover every route uniformly.
5. **Rewrite `src/app/sitemap.ts`.** Replace the ten arrays with:
   - A `ROUTE_CLASS` map from English path to a class (`primary`, `core`, `cluster`, `insights`, `info`, `legal`), covering every non-noindex `EN_ROUTES` entry. Use a `Record<(typeof EN_ROUTES)[number], RouteClass>` so TypeScript fails the build if a route is added without a class — that is the anti-drift mechanism.
   - A `CLASS_SETTINGS` map from class to `{ priority, changeFrequency }`, keeping today's values: primary 0.95 weekly, core 0.8 weekly, cluster 0.75 monthly, insights 0.7 monthly, info 0.4 monthly, legal 0.4 monthly.
   - A `LAST_MODIFIED` per-route map, seeded from today's `REVIEW_DATES` values, with a comment saying the release that changes a page updates its date here.
   - A single `LOCALE_PAIRS.flatMap` that emits the three locale URLs per route with `alternatesFor(path)` unchanged.
   Export `NOINDEX_ROUTES` from `src/lib/locale-routes.ts` so the test and the sitemap share one list.
6. `npm test` — green. Diff the new `/sitemap.xml` against `/tmp/sitemap-before.xml` and account for every added and removed URL in the hand-back. A URL that disappears must be a noindex route or a duplicate.
7. **Schema parity — Course and CourseInstance on the localised intake pages.** Read the English `/intakes` schema block and mirror it into `src/app/(ms)/ms/intakes/page.tsx` and `src/app/(zh)/zh/intakes/page.tsx`. `name`, `description` and `courseMode` text come from `CORE_PAGES_MS.intakes` / `CORE_PAGES_ZH.intakes`; dates and cohort ids come from `INTAKES`. Keep the stable `@id` scheme from `seo.ts:8-14`.
8. **`Person` on the localised About pages.** Mirror the English `/about` `Person` block into `src/app/(ms)/ms/about/page.tsx` and `src/app/(zh)/zh/about/page.tsx`, with `name` unchanged (a person's name is not translated) and `jobTitle`/`description` from the merged Malay and Chinese copy.
9. **`ItemList` + `Person` on the localised faculty pages.** Same treatment for `src/app/(ms)/ms/faculty/page.tsx` and `src/app/(zh)/zh/faculty/page.tsx`.
10. After each schema addition run `npm run build && npm run audit:release` — it parses every JSON-LD block and will catch a malformed one immediately. Also validate one representative block per type against schema.org's expected properties by reading the rendered HTML.
11. **OpenGraph Chinese glyphs.** In `src/app/opengraph-image/route.tsx`, replace `fontFamily: "Arial, sans-serif"` with a bundled font. Subset Noto Sans SC to the glyph set actually used by the Chinese OG titles, place it under `src/app/opengraph-image/`, load it with `fs.readFileSync` and pass it in the `ImageResponse` `fonts` array. Keep `force-static`, keep 1200x630. Malay and English keep the Latin font. Verify the subset is small enough not to blow the route's build time — report the file size.
12. Regenerate and eyeball the OG image for a Chinese route; confirm no tofu boxes.
13. Run the full gate (see Acceptance), then `npm run release:sync && npm run release:check`.
14. Commit as: sitemap test; sitemap derivation; intake schemas; about schemas; faculty schemas; OG font.

Plus:

- The sitemap unit test passes, including the exact-count assertion.
- `curl -s http://localhost:3000/sitemap.xml | grep -c "<loc>"` equals `3 * (37 - 7)` = **90**. Report the actual number; if it differs, explain every difference.
- No noindex route appears in `/sitemap.xml` in any locale — prove it with a grep for each of the seven paths.
- `npm run audit:release` reports valid JSON-LD on every indexed page and no broken internal targets.
- The rendered `/ms/intakes` and `/zh/intakes` HTML each contain `"@type":"Course"` and `"@type":"CourseInstance"`; `/ms/about` and `/zh/about` each contain `"@type":"Person"`; `/ms/faculty` and `/zh/faculty` each contain `"@type":"ItemList"` and `"@type":"Person"`.
- The OpenGraph image for a Chinese route renders every glyph. State the subset font's byte size.

## Out of scope

Any copy change (R2.x). Email templates (R3.1). PDFs (R3.2). `llms.txt` and `llms-full.txt` (R3.4). Adding new schema types beyond the four named in the spec. Changing the noindex policy for any route. **Submitting URLs via `/api/internal/indexnow`** — that is a post-deployment action the architect triggers after the release is live, not part of this brief.
