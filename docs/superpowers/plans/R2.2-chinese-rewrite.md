# R2.2 — Chinese rewrite

## Goal

Rewrite the Chinese site so it reads as Malaysian Simplified Chinese (zh-Hans-MY) editorial copy in the register defined by `docs/superpowers/research/zh-register.md`, not as mainland Chinese and not as a translation of the English. One executor handles **one unit** from the table below per dispatch. Facts, numbers and controlled terms are imported constants and are never retyped.

## Model and role

- **Writer: Opus.** Rewrites the assigned unit.
- **Reviewer: Opus, separate agent, fresh context.** Runs section 7 of `zh-register.md` as a checklist plus the commands in Acceptance. Returns PASS, or FAIL with file:line references.
- **Loop limit: two.** Writer → reviewer → (fail) → writer → reviewer. A third failure stops the unit and escalates to the architect with the reviewer's last report. Do not attempt a third rewrite.

## Inputs — read these first, in full

1. `docs/superpowers/specs/2026-09-03-site-quality-programme-design.md` sections 2, R2.0, R2.2.
2. `docs/superpowers/research/zh-register.md` — **section 3 "Recommended register mix per page type"** (find your page type's row and obey its address form, sentence length, decoration score, CTA style and model sentence), **section 4 "Glossary — EN → Malaysian zh-Hans for site terms"** (55 rows; `[OFFICIAL]` entries are verbatim, `[AVOID]` entries are forbidden), **section 5 "Do / Don't"** with its three sub-blocks *Register and structure*, *Vocabulary* and *Typography* (29 numbered rules), **section 6 "Audit of the current site Chinese — 15 most important problems"** plus its *Secondary items* list (worked corrections — reuse them where they touch your unit), **section 7 "Self-validation checklist for the rewriting agent"** (18 checks; the reviewer runs all 18).
3. `SEO-CONTENT-GOVERNANCE.md` — the Clarity standard, Voice and tone, and Controlled terminology tables.
4. The English source of your unit, for meaning only: the `(en)` twin of your file path.
5. `src/lib/content.ts` — the constants you import. Never edit English strings here.

## Constraints

- **Facts are imported constants and are never retyped.** Every number, fee, duration, cohort id, date and module count comes from `FACTS`, `INTAKES`, `SITE`, `PROGRAMME_PROOF`, `HRD_CORP_CLAIM_ZH`, `PROGRAMME_AUDIENCE_ZH`, `REFUND_TERMS_ZH`, `CTA_LABELS.zh` and their siblings. If you find yourself typing `RM10,000.00`, `6 个月` or `12 个模块` as a literal, interpolate instead.
- **Register rules, verbatim from spec section R2.2:** *Register per `zh-register.md` section 3. Key rules: at most one decorative four-character phrase or parallel structure per heading and two per paragraph, none on fee or recognition pages; numbers before adjectives in ledes; Malaysian lexis (`令吉, 大专, 报读, 进修, 首席执行员, 管道, 数码, 行销`) and never the mainland forms listed in the guide; `学员` for participant, `届/班` for cohort; `认证` reserved for MQA, `认可` for CMI; EMBA glossed once as 高级工商管理硕士 then Latin; full-width punctuation and pangu spacing as already implemented; `免费索取` not `免费获取`; no urgency phrases.*
- **Headline limits:** Chinese H1 **<= 14 characters**, two beats. Sub-headline <= 45 characters. Body sentence length per the section 3 row for your page type (hero body 20–30; programme 20–35 with a 25–35 lede; fees 15–30 declarative, one condition per sentence; FAQ answers 1–3 sentences of 15–35; insights varied 12–45; campaign 20–30).
- **Banned patterns.** `scripts/content-clarity-audit.mjs` gained a Chinese list in R1.2 (`班次`, `参与者`, `诚实边界`, `颁授并背书`, `身份启用`, `折扣码`, `免费获取`, `渠道`, `创始人`, `首席执行官`, `营销`). Your unit must produce **zero** hits under `node scripts/content-clarity-audit.mjs --strict-locales` for the file you touched.
- **Do not change positioning, claims or scope.** Same meaning, different Chinese. If a sentence's English meaning is wrong, report it; do not fix it here.
- **Branch and release action.** One branch per unit: `feat/r2-2-chinese-<unit-slug>`, e.g. `feat/r2-2-chinese-fees` for unit 6. Pushing your feature branch to GitHub for CI is allowed. Merging into `codex/hostinger-deployment` and pushing that branch **is the deployment**; it happens only after the full section-6 gate is green for the whole release. Never do that from a unit.
- Hostinger configuration is out of scope for the whole programme.
- **Known blocker on unit 1.** `src/lib/__tests__/fact-parity.test.ts:50` asserts `PROGRAMME_POSITIONING_ZH` contains `"颁授并背书"` — the exact phrase `zh-register.md` section 6 item 11 bans as finance-register. Unit 1 must change that assertion to the corrected wording (recognition as `获…认可`, awarding as `颁发认可证书`) **in the same commit**, test first. No other unit may edit that test.
- **Known blocker on unit 8.** `班次` is on the banned list and is currently the zh column header in `src/components/site/IntakeSchedule.tsx:40` and the wording at line 53. Unit 8 replaces both with `届`/`班` forms per glossary row 36 and section 6 item 12.

## Steps

**Writer**

1. Branch: `git checkout codex/hostinger-deployment && git checkout -b feat/r2-2-chinese-<unit-slug>`.
2. Read the five Inputs. Then read your unit's file(s) in full and the `(en)` twin for meaning.
3. Identify your page type in `zh-register.md` section 3 and write down its address form, sentence length, **decoration score** and CTA style before writing a character. Fee and recognition pages are decoration score 0–1: no 四字词, no 对仗, no 排比.
4. Rewrite. Metadata (`title`, `description`, OpenGraph) and every JSON-LD text field on the page are rewritten with the body — they are part of the unit.
5. Replace every literal fact with the imported constant. Add the import if it is missing.
6. Apply the typography rules (section 5, rules 21–29) deliberately: full-width `，。：；？！（）、——`; `""` quotes, never `「」`; full-width brackets around Latin glosses inside Chinese text; the site's existing pangu spacing, applied consistently and never inside an official string (`RM10,000.00`, `e-TRiS`, `fCMgr`); Arabic numerals throughout one passage; no traditional glyphs.
7. Self-run `zh-register.md` section 7 checks 1–18 against your own output before handing over. Fix what you find.
8. `npm run lint && npm run typecheck && npm test && npm run audit:content && node scripts/content-clarity-audit.mjs --strict-locales` — the strict run must show zero hits **in your file**.
9. Commit as `feat(zh): rewrite <unit name> in the Malaysian Chinese site register`. Hand to the reviewer with: the unit number, the branch name, the diff, and your section 7 self-check results.

**Reviewer (fresh Opus, no writer context)**

10. Read `zh-register.md` sections 3–7 and `SEO-CONTENT-GOVERNANCE.md`. Read the diff, not the conversation.
11. Run all 18 checks in section 7 against the changed file(s). Record each as pass or fail with a `file:line`.
12. Run the commands in Acceptance.
13. Grep the banned lexis explicitly: `参与者|离岗|差旅|宣传册|获取|渠道|创始人|首席执行官|账户|数字化|营销|班次|批次|打工人|身份启用|衔称|背书|面向未来|颁授并背书|折扣码|诚实边界|约\s*\d|大约|通常|一般|名额有限|先到先得|立即报名` — expect zero in the changed files. Also grep for half-width `,` and `.` inside Chinese runs, and for traditional glyphs `豐|優|著`.
14. Verify every fact value against `content.ts` and confirm none was retyped as a literal.
15. Count characters in every rewritten H1: **<= 14 characters**. Count 四字词 and 对仗 per heading (max 1) and per body paragraph (max 2); zero on fee and recognition pages.
16. Return **PASS**, or **FAIL** with a numbered list of `file:line` + the failing section-7 check number + the required correction. Do not rewrite the copy yourself.
