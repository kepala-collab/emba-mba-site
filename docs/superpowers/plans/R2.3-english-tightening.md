# R2.3 — English tightening

## Goal

Apply the clarity rules already encoded in `scripts/content-clarity-audit.mjs` and `SEO-CONTENT-GOVERNANCE.md` to every English page, and align the English CTA family and headline lengths with the rewritten Malay and Chinese so the three sites read as one product. No fact, claim or positioning changes. The final task of this brief turns on `--strict-locales`, which closes Release 2.

## Model and role

- **Writer: Opus.** Rewrites the assigned unit.
- **Reviewer: Opus, separate agent, fresh context.** Runs the checklist in this brief plus the commands in Acceptance. Returns PASS, or FAIL with file:line references.
- **Loop limit: two.** A third failure escalates to the architect.

## Inputs — read these first, in full

1. `docs/superpowers/specs/2026-09-03-site-quality-programme-design.md` sections 2, R2.0, R2.3.
2. `SEO-CONTENT-GOVERNANCE.md` — the whole file. The **Clarity standard**, **Voice and tone** and **Controlled terminology** table are the rulebook for this brief.
3. `scripts/content-clarity-audit.mjs` — read all 29 banned patterns at lines 24–51 and the nine canonical fact statements at lines 74–84. These are the rules you are applying by hand to prose the regex cannot reach.
4. The **already-merged** Malay and Chinese versions of your unit, for CTA and headline alignment: the `(ms)` and `(zh)` twins of your file path. If R2.1 and R2.2 have not merged their matching unit, stop and say so — alignment is impossible against unrewritten copy.
5. `src/lib/content.ts` — `CTA_LABELS` (line 32) is the CTA family source of truth.

## Constraints

- **No fact or positioning changes.** Not one number, price, date, duration, cohort id, credential phrase or HRD Corp condition moves. The nine canonical statements the audit checks at lines 74–84 of `content-clarity-audit.mjs` are byte-locked; if you touch `content.ts`, `npm run audit:content` will tell you immediately.
- **Facts are imported constants and are never retyped.** Same rule as R2.1 and R2.2.
- **CMI recognition wording is locked by `src/lib/__tests__/fact-parity.test.ts:48`** (`PROGRAMME_POSITIONING_SENTENCE` must contain `awarded and endorsed by CMI`). Do not change it. Unlike the Malay and Chinese assertions, the English one is correct and stays.
- **Alignment means structural parity, not translation.** Match the *number* of CTAs per view, the CTA verb+object+purpose shape, and the headline length band. Do not calque Malay or Chinese phrasing into English.
- **Headline limits:** English H1 <= 12 words, one clear claim, sentence case. Body sentence length: hero and campaign 12–20 words; programme and FAQ 15–25; fees 15–25 with one condition per sentence; insights 20–30.
- **Branch and release action.** One branch per unit: `feat/r2-3-english-<unit-slug>`. Pushing your feature branch to GitHub for CI is allowed. Merging into `codex/hostinger-deployment` and pushing that branch **is the deployment**; it happens only after the full section-6 gate is green for the whole release.
- Hostinger configuration is out of scope for the whole programme.
- **Unit 38 is the release-closing task** and runs only after every other R2.1, R2.2 and R2.3 unit has merged.

## Steps

**Writer (units 1–37)**

1. Branch: `git checkout codex/hostinger-deployment && git checkout -b feat/r2-3-english-<unit-slug>`.
2. Read the five Inputs, then your unit's file(s) in full, then the merged `(ms)` and `(zh)` twins.
3. Build a three-column alignment note before editing: for each CTA and each heading on the page, write the current EN, the merged MS and the merged ZH. This note is part of the hand-back.
4. Tighten the English. In order of priority:
   - Remove every qualifier before a number (`roughly`, `approximately`, `typically`, `usually`, `commonly`, `often`, `most`, `about`, `~`). Replace with the exact fact or delete the claim.
   - Name the decision-maker and the controlling document in every fee, scholarship, refund, HRD Corp and CMI sentence.
   - Remove prestige labels, urgency devices and implied guarantees.
   - Cut sentences to the length band for the page type. Split, do not comma-splice.
   - Align the CTA to the `CTA_LABELS` family and to the MS/ZH shape: verb + object + purpose. One primary CTA per view.
   - Bring the H1 to <= 12 words and sentence case.
5. Rewrite metadata (`title`, `description`, OpenGraph) and JSON-LD text fields with the page. Meta descriptions must stay **<= 180 characters** — `scripts/release-audit.mjs:70` enforces this.
6. Replace any literal fact with the imported constant.
7. `npm run lint && npm run typecheck && npm test && npm run audit:content && npm run build && npm run audit:release`.
8. Commit as `feat(en): tighten <unit name> and align its CTA family`. Hand to the reviewer with the unit number, branch, diff and alignment note.

**Reviewer (fresh Opus, no writer context)**

9. Read `SEO-CONTENT-GOVERNANCE.md` and the diff. Run the Acceptance commands.
10. Checklist, each recorded pass/fail with a `file:line`:
    1. No qualifier before any number anywhere in the diff.
    2. Every conditional outcome names its decision-maker and controlling document.
    3. No prestige label, superlative, urgency device or guarantee.
    4. Controlled terminology table obeyed — every "Use" form present, no "Do not substitute" form anywhere.
    5. H1 <= 12 words, sentence case, one claim.
    6. Sentence lengths inside the band for the page type.
    7. Exactly one primary CTA per view; CTA is verb + object + purpose.
    8. CTA family and headline length band match the merged MS and ZH twins (check the writer's alignment note against the actual files).
    9. Meta description <= 180 characters.
    10. Every fact is an interpolated constant, not a literal.
    11. No fact, number, date, price or claim changed — diff the semantic content, not just the words.
    12. `git diff` shows no change to any Malay or Chinese string.
11. Return **PASS**, or **FAIL** with numbered `file:line` corrections.

**Unit 38 only**

12. Confirm every R2.1, R2.2 and R2.3 unit has merged into `codex/hostinger-deployment`. Run `node scripts/content-clarity-audit.mjs --strict-locales` and confirm it exits **0** with no Malay or Chinese hits anywhere. If it exits 1, stop: name the remaining unit that owns each hit and escalate. Do not fix another unit's copy.
13. Change `"audit:content"` in `package.json` to `node scripts/content-clarity-audit.mjs --strict-locales`. Run the full gate. Commit as `chore(audit): enforce the Malay and Chinese register lists`.
