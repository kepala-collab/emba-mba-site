# R1.2 — Gate repair and CI

## Goal

Make every automated gate runnable and honest: extend the content clarity audit to Malay and add Malay and Chinese banned-pattern lists behind a `--strict-locales` flag that is off in Release 1, turn on CI for pushes to the working branch, and fix the Malay and Chinese intake tables that render English month abbreviations. No copy is rewritten here — only the machinery that will police it.

## Model and role

Sonnet, single technical executor. No reviewer pass.

## Constraints

- **Facts never change.** `INTAKES` in `content.ts` keeps its English canonical strings (`22–23 Aug`, `Sat–Sun`, `9am–6pm`). You are adding a *rendering* layer, not editing the data.
- **Do not fix any copy the new patterns flag.** Release 1 adds detection only. R2.1 and R2.2 clear the hits.
- **Branch and release action.** Create `feat/r1-2-gate-repair-ci` from `codex/hostinger-deployment`. **Push this feature branch to GitHub** — this brief's acceptance requires a real CI run on a `codex/**`-adjacent branch. Merging into `codex/hostinger-deployment` and pushing that branch **is the deployment**; it happens only after the full section-6 gate is green. Never do that from this brief.
- Hostinger configuration is out of scope for the whole programme.
- `scripts/release-audit.mjs` is owned by R1.1. Do not touch it here. If R1.1 has not merged yet, `npm run audit:release` will fail for reasons unrelated to your change; note that in the hand-back and do not "fix" it.
- **Map correction:** the spec points at `src/app/(ms)/ms/intakes/page.tsx` for the date bug. That page only renders `<IntakeSchedule lang="ms" />` at line 35. The English month strings are printed by `src/components/site/IntakeSchedule.tsx` at lines 128–130 and 134 (table) and 169–171 and 173 (mobile cards). Fix it there.
- **Known consequence:** the Chinese banned list includes `班次`, which `IntakeSchedule.tsx` currently uses as the zh column header at line 40 and at line 53. That is why the new locale patterns must warn, not fail, in Release 1.

## Steps

1. `git checkout codex/hostinger-deployment && git checkout -b feat/r1-2-gate-repair-ci`.
2. **Malay file coverage.** In `scripts/content-clarity-audit.mjs`, add `"src/lib/content-ms.ts"` to the `files` array (after `"src/lib/content-zh.ts"`, line 10). Run `npm run audit:content` and record whether it still exits 0. If any existing pattern now fires on `content-ms.ts`, report the hit in the hand-back and do **not** edit the Malay copy — instead confirm with the architect. The 29 current patterns are English- and Chinese-oriented, so a clean pass is expected.
3. **Add the flag.** Near the top of the script add:
   ```js
   const strictLocales = process.argv.includes("--strict-locales");
   ```
   and a second collection `const warnings = [];`.
4. **Malay pattern list.** Add a `bannedMs` array. Minimum contents, taken from `ms-register.md` section 7 check 6 and the spec:
   ```js
   const bannedMs = [
     ["Malay undefined norm", /\b(?:biasanya|kebiasaannya|selalunya|kebanyakan|lebih kurang|kira-kira)\b/i],
     ["Malay wrong endorsement verb", /disokong(?:\s+\w+){0,3}\s+CMI|CMI(?:\s+\w+){0,3}\s+disokong/i],
     ["Malay software-application calque", /\bprojek aplikasi\b/i],
     ["Malay working-manager calque", /\bpengurus bekerja\b/i],
     ["Malay non-collocation CTA", /\bperbualan program\b/i],
     ["Malay government-programme calque", /\bprogram awam\b/i],
     ["Malay Chartered Manager as next stage", /\blaluan lanjutan\b/i],
   ];
   ```
5. **Chinese pattern list.** Add a `bannedZh` array. Minimum contents, from `zh-register.md` section 7 check 11 and the spec:
   ```js
   const bannedZh = [
     ["Chinese transport-schedule cohort word", /班次/],
     ["Chinese wrong participant noun", /参与者/],
     ["Chinese honest-boundary calque", /诚实边界/],
     ["Chinese finance-register endorsement", /颁授并背书/],
     ["Chinese status calque", /身份启用/],
     ["Chinese e-commerce framing", /折扣码/],
     ["Chinese app-store CTA verb", /免费获取/],
     ["Chinese mainland lexis", /渠道|创始人|首席执行官|营销/],
   ];
   ```
   Keep `免费获取` as its own entry so the CTA hit is legible in the output.
6. **Wire the lists.** In the per-file loop, run `bannedMs` only against files whose normalised path contains `content-ms.ts`, `/(ms)/`, `lead-email.ts` or `nurture-email.ts`; run `bannedZh` only against files whose normalised path contains `content-zh.ts`, `/(zh)/`, `lead-email.ts` or `nurture-email.ts`. Run both against `src/components/site/**` (the shared components carry all three locales). Push each hit into `failures` when `strictLocales` is true, otherwise into `warnings`.
7. **Report.** After the existing failure block, add:
   ```js
   if (warnings.length > 0) {
     console.warn(`Locale register warnings (${warnings.length}) — not blocking in Release 1:\n` + warnings.join("\n"));
   }
   ```
   Warnings must never change the exit code while the flag is off.
8. Run `npm run audit:content` — exit 0, with a warnings block listing the known Malay and Chinese hits. Then run `node scripts/content-clarity-audit.mjs --strict-locales` — it must exit 1 and list those same hits as failures. Record both counts.
9. **Do not** add `--strict-locales` to `package.json` here. The last task of Release 2 (see `R2.3-english-tightening.md`, final step) flips `"audit:content"` to `node scripts/content-clarity-audit.mjs --strict-locales`.
10. **CI trigger.** In `.github/workflows/quality.yml`, change lines 5–6 to:
    ```yaml
      push:
        branches: [main, "codex/**"]
    ```
    Leave `pull_request:` and every step unchanged.
11. **Locale date rendering — write the test first.** Add `src/lib/__tests__/intakes.test.ts` asserting:
    - `formatIntakeDateRange("22–23 Aug", "ms") === "22–23 Ogos"`
    - `formatIntakeDateRange("17–18 Oct", "ms") === "17–18 Okt"`
    - `formatIntakeDateRange("4–5 Dec", "ms") === "4–5 Dis"`
    - `formatIntakeDateRange("19–20 Sep", "ms") === "19–20 Sep"` (unchanged, but must be intentional)
    - `formatIntakeDateRange("22–23 Aug", "en") === "22–23 Aug"`
    - `formatIntakeDateRange("22–23 Aug", "zh") === "8 月 22 至 23 日"`
    - `formatIntakeTime("9am–6pm", "ms") === "9 pagi hingga 6 petang"`
    - `formatIntakeTime("9am–6pm", "zh") === "上午 9 时至下午 6 时"`
    - `formatIntakeTime("9am–6pm", "en") === "9am–6pm"`
    Run `npm test` and confirm these fail with "not a function".
12. **Implement.** Add `formatIntakeDateRange(range: string, locale: SiteLocale): string` and `formatIntakeTime(time: string, locale: SiteLocale): string` to `src/lib/intakes.ts`. Import `SiteLocale` from `@/lib/locale-routes`. Map English month abbreviations to `{Jan, Feb, Mac, Apr, Mei, Jun, Jul, Ogos, Sep, Okt, Nov, Dis}` for `ms`; for `zh`, emit `<n> 月 <d1> 至 <d2> 日` using the site's existing pangu spacing. Return the input unchanged for `en`. Handle the en-dash `–` (U+2013) that `INTAKES` actually uses, not a hyphen.
13. Run `npm test` — the new tests pass.
14. **Use the helpers.** In `src/components/site/IntakeSchedule.tsx`: import both helpers; replace `{cohort.s1}`/`{cohort.s2}`/`{cohort.s3}` at lines 128–130 and 169–171 with `{formatIntakeDateRange(cohort.s1, lang)}` etc.; replace `{cohort.time}` at lines 134 and 173 with `{formatIntakeTime(cohort.time, lang)}`. Leave the `days` ternaries alone — they already localise.
15. Run the full gate (see Acceptance). Commit as three commits: the audit change, the CI change, and `fix(intakes): render cohort dates and times in the page locale` (tests first inside that commit).
