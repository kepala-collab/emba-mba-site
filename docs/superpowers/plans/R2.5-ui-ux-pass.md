# R2.5 — UI and UX pass

## Goal

The Malay and Chinese rewrites change string lengths and line-break behaviour across the site. Sweep six breakpoints in three languages, find the layout, accessibility and hierarchy defects the new copy exposes, add a Playwright assertion for each defect found, and fix them inside the existing design system.

## Model and role

Sonnet, single technical executor. No language reviewer — this brief changes CSS and markup, not copy. If a fix would require rewording, stop and hand the string back to the owning R2.1/R2.2/R2.3 unit.

## Inputs — read these first, in full

- `docs/superpowers/specs/2026-09-03-site-quality-programme-design.md` (section R2.5)
- `e2e/site-smoke.spec.ts` — the existing axe tests at lines 528, 604 and 829; the overflow test at 377; the narrow-layout tests at 349 and 364; the Turnstile 320px test at 920; the consent banner test at 587
- `src/app/globals.css` — the breakpoint blocks at `max-width:1080`, `max-width:820`, `max-width:640` (lines ~1440, ~1451, ~1463 onward)
- `scripts/style-budget-audit.mjs` — the three ceilings you must not exceed
- `playwright.config.ts`

## Constraints

- **Facts never change and copy never changes.** Not one word, in any language. If the only way to fix an overflow is to shorten a string, that is a copy defect: record it, name the R2.1/R2.2/R2.3 unit that owns the file, and hand it back. Do not edit the string yourself.
- **Fix inside the existing design system.** No new components unless a defect provably cannot be fixed otherwise; if you add one, justify it in the hand-back with the fix you tried first and why it failed.
- **Style budgets are hard limits.** `scripts/style-budget-audit.mjs` caps inline `style={` at 723, `<style` at 17 and `!important` at 37 across `src`. Prefer a class in `globals.css` over an inline style; never add an `!important` to win a specificity fight you could win with a better selector.
- **Every fix gets a test.** A defect you fix without adding an assertion will regress. The assertion goes in `e2e/site-smoke.spec.ts` and must fail against the pre-fix code.
- **Branch and release action.** Create `feat/r2-5-ui-ux-pass` from `codex/hostinger-deployment`. Pushing the feature branch for CI is allowed. Merging into `codex/hostinger-deployment` and pushing that branch **is the deployment**; only after the section-6 gate is green.
- Hostinger configuration is out of scope.
- **Run this brief last in Release 2**, after every R2.1, R2.2, R2.3 and R2.4 unit has merged. Sweeping before the copy is final measures strings that will change.
- **`globals.css` and `site-smoke.spec.ts` are exclusive.** No other brief may run in parallel with this one (see `README.md`).

## Steps

1. `git checkout codex/hostinger-deployment && git checkout -b feat/r2-5-ui-ux-pass`. Confirm the R2 copy has merged (`git log --oneline | grep -c "feat(ms)\|feat(zh)\|feat(en)"`) and record the count.
2. `npm run build && npm start`. Every sweep runs against this production build.
3. **The sweep.** Breakpoints **320, 375, 390, 768, 1024, 1440**. Priority routes, in all three languages (English at `/…`, Malay at `/ms/…`, Chinese at `/zh/…`): home, `/executive-mba`, `/fees`, `/apply`, `/intakes`, `/faq`, `/chartered-manager-malaysia`, `/curriculum`, `/resources/advancement-brief`, one insight article, `/lp/google`. That is 6 breakpoints x 11 routes x 3 languages; automate it with a scratch Playwright script that screenshots and measures rather than clicking through by hand.
4. **What to check at each cell**, recording a pass/fail with route, width, language and selector:
   1. **No horizontal overflow.** `document.documentElement.scrollWidth <= clientWidth`, and per-element `scrollWidth <= clientWidth` for tables, code blocks, breadcrumb bars and the intake region. Malay strings are the longest; expect failures here first.
   2. **CJK line-height and heading wrap.** Chinese headings must not wrap to a single orphaned character; body line-height must be comfortable for CJK (the R1.6 fallback stack changes metrics).
   3. **Form labels and errors** render fully in all three languages: no clipped label, no error message overlapping the next field, no label truncation with an ellipsis.
   4. **CTA hierarchy:** exactly one primary CTA visible per viewport-height of scroll. Count `.btn` primary variants in the first viewport.
   5. **Focus states** visible on every interactive element: tab through the page and confirm a visible outline on links, buttons, form fields, the skip link and the assistant trigger.
   6. **Skip link** appears on first Tab and moves focus to main content.
   7. **Breadcrumb wrap** at 320 without overflow and without a broken separator.
   8. **Table regions** (`ScrollableTableRegion`) scroll rather than overflow, and announce their scroll hint in the page language.
   9. **Consent banner height at 320** does not cover the primary CTA or exceed roughly a third of the viewport.
   10. **Axe** clean on each priority route in each language.
5. **Record every defect** in a table: route, width, language, selector, what is wrong, and the proposed fix. This table is the core of the hand-back. Classify each as *layout defect* (yours) or *copy defect* (hand back to the owning unit).
6. **For each layout defect, in order of severity:**
   a. Add a Playwright assertion in `e2e/site-smoke.spec.ts` that reproduces it. Run it and confirm it FAILS.
   b. Fix it in `globals.css` or the owning component.
   c. Run the assertion again and confirm it PASSES.
   d. Re-run the whole sweep cell for that route and width — fixes at one breakpoint often break another.
7. **Extend the axe coverage.** The existing suite runs axe at lines 528, 604 and 829 on a subset. Add Malay and Chinese variants for each priority route not already covered. Axe must return zero violations, not "zero serious violations".
8. Run `npm run audit:styles` after every batch of CSS edits and confirm the three counts are still under their ceilings. Report the final three numbers.
9. Run the full gate (see Acceptance).
10. Commit one defect per commit where practical: `fix(ui): <defect> at <width> on <route>`, each containing its test and its fix.

## Acceptance

Every command exits 0.

```
npm run lint
npm run typecheck
npm test
npm run audit:content
npm run audit:styles
npm run validate:env:contract
npm run build
npm run audit:seo
npm run audit:release
npm run test:e2e
```

Plus:

- **Axe returns zero violations** on all eleven priority routes in all three languages.
- **Zero horizontal overflow**: `scrollWidth <= clientWidth` on `documentElement` at all six breakpoints on all eleven routes in all three languages.
- **Style budget within limits**: report the three counts from `npm run audit:styles` and confirm each is at or below 723 / 17 / 37.
- Every defect in your table is either fixed with a passing new assertion, or handed back as a copy defect with the owning unit named.
- The e2e suite has grown by at least one test per fixed defect, and the full suite is green.

## Out of scope

Any copy change in any language. Design-system replacement (excluded by spec section 2). New pages or components, unless justified per the Constraints. Performance work (R1.6 owns Lighthouse). Schema or sitemap changes (R3.3). Refactoring `globals.css` beyond the specific fixes.

## Hand-back

1. Full stdout of every Acceptance command.
2. **The defect table**: route, width, language, selector, defect, classification (layout/copy), fix or hand-back target. Every cell you swept that failed, including ones you decided not to fix and why.
3. The count of sweep cells run (expected 198) and how many passed on the first sweep.
4. For each fixed defect: the new test name, the pre-fix failure output, the file changed, and the post-fix pass.
5. Axe results per route per language: violation count, expected 0.
6. The three `npm run audit:styles` numbers, before and after.
7. Any new component you added, with the justification required by the Constraints.
8. The list of copy defects handed back, each naming the R2.1/R2.2/R2.3 unit and file that owns it.
9. `git diff --stat codex/hostinger-deployment..feat/r2-5-ui-ux-pass`.
