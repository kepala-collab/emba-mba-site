# R3.2 — PDF regeneration from final copy

## Goal

Bring the twelve PDFs up to the same register as the rewritten site. R1.5 moved their text into `scripts/pdf/copy/<lang>.json` verbatim; this brief runs the writer/reviewer register check over that text, applies the Malay guide's new display title, and regenerates all twelve deterministically. Structure, facts, page counts and filenames are preserved.

## Model and role

- **Opus writer + separate Opus reviewer** for the Malay and Chinese copy, one document per language per dispatch. Loop limit two.
- **Sonnet** for the English pass, the regeneration run and the proof inspection.

## Constraints

- **The existing PDF text is the approved baseline, not draft material.** The nine `future-ready-*` documents are the owner-confirmed follow-up library named in `HANDOFF.md` (spec assumption 3). You are applying register corrections to approved text, not rewriting from scratch. Preserve every fact, every structural element and every section order.
- **Facts never change.** Every number, fee, date, duration and controlled identifier stays exactly as the JSON already carries it. The register pass changes *how* a sentence reads, never *what* it asserts. If a register fix would change a fact, the fix is wrong.
- **Filenames never change.** All twelve stay as they are, including `panduan-pengurus-bekerja-2026.pdf`. The Malay guide's **displayed title** changes per R2.1 (`pengurus bekerja` → `pengurus yang sedang bekerja` / `profesional yang bekerja`); the URL does not.
- **Page counts never change**: 3 / 4 / 3 / 3. If a longer Malay sentence pushes a page, shorten the sentence within the register rather than adding a page.
- **Determinism is non-negotiable.** After regeneration, a second `npm run pdfs:build` must leave `git diff --exit-code public/downloads` clean.
- **Branch and release action.** One branch per unit: `feat/r3-2-pdf-<document>-<lang>`. Pushing feature branches for CI is allowed. Merging into `codex/hostinger-deployment` and pushing that branch **is the deployment**; only after the section-6 gate is green.
- Hostinger configuration is out of scope. Locally the interpreter is `py -3`; `scripts/pdf/run.mjs` resolves it.
- Run this brief **after** R1.5 has merged (the pipeline must exist) **and** after R2.1, R2.2 and R2.3 have merged (the site copy is the register reference).

## Steps

**Writer (units 1–12)**

1. Branch: `git checkout codex/hostinger-deployment && git checkout -b feat/r3-2-pdf-<document>-<lang>`.
2. Read the guide's **PDF guides** row in section 3 — for Malay: roles plus `anda` in the intro, tables in noun phrases, intro 15–20 words, AeU-brochure register, back-page contact block. For Chinese: `您`, document voice (`本指南`), section openers 25–35 characters, decoration 2 in openers and **0 in tables**, last-page CTA only.
3. Read your document's language block in the copy JSON and the corresponding merged site copy for the same subject.
4. Apply register corrections **in place**, key by key. Do not restructure, do not reorder blocks, do not merge or split sections. If a block is already in register, leave it byte-identical.
5. Unit 2 additionally changes the Malay guide's **displayed title** away from `Pengurus Bekerja` per R2.1. The filename stays.
6. Verify the JSON still parses and every key that existed before still exists: `node -e "JSON.parse(require('fs').readFileSync('scripts/pdf/copy/<lang>.json','utf8'))"` and a key-set diff against the pre-edit file.
7. `npm run pdfs:build`, then inspect your document's PDF: page count unchanged, no orphaned heading, no overflowing table cell.
8. Commit as `feat(pdf): apply the <lang> register to <document>`. Hand to the reviewer with the JSON diff and the regenerated PDF.

**Reviewer (fresh Opus, no writer context; Sonnet for English units)**

9. Run section 7 of the matching guide (20 Malay checks / 18 Chinese checks) against the changed JSON block. Record each pass/fail with a JSON key path.
10. Verify every fact against `content.ts` / `content-ms.ts` / `content-zh.ts`: fee, duration, training days, sessions, module count, cohort ids and dates, LIFE Innoversity, CMI, MQA, HRD Corp, e-TRiS, Allowable Cost Matrix. Any drift is a FAIL.
11. Confirm the page count matches the baseline and the filename is unchanged.
12. Return PASS, or FAIL with key paths and required corrections.

**Unit 13 — regeneration and proof**

13. Confirm all twelve copy units have merged. `npm run pdfs:build`.
14. Run `npm run pdfs:build` a second time and require `git diff --exit-code public/downloads` to be clean.
15. `py -3 scripts/render-lead-magnet-pdfs.py`. Open every proof PNG for all twelve documents. Check: no tofu boxes or missing glyphs (Chinese especially), no clipped text, no table cell overflow, no orphaned heading at a page break, the navy header bar and gold rule intact on every page.
16. `npm run pdfs:check` — exits 0.
17. Run the full gate plus `npm run release:sync && npm run release:check`, since `public/` changed.
