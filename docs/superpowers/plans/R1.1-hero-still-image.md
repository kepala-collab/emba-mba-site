# R1.1 — Hero still image

## Goal

Replace the home-page hero video with a single sharp still image so nothing on `/home`, `/ms` or `/zh` plays choppily. Remove the video element, its readiness effect, its play/pause control, its CSS and its build assets, and move the release gate from a video budget to an image budget. The component must accept a higher-resolution replacement image later with no code change.

## Steps

1. `git checkout codex/hostinger-deployment && git checkout -b feat/r1-1-hero-still`.
2. **Produce the stopgap asset.** Extract the sharpest frame from `public/media/future-commerce/future-ready-emba-leadership-hero-v8.mp4` at its native 1280x720 to a temporary PNG (for example `ffmpeg -i public/media/future-commerce/future-ready-emba-leadership-hero-v8.mp4 -vf "select=eq(n\,120)" -vframes 1 tmp/hero-frame.png`; step through candidate frames and pick the one with the crispest subject edges). Create `assets/hero/` at the repo root and save the chosen PNG as `assets/hero/hero-leader-master.png`. `assets/` is outside `public/`, so it never ships.
3. Encode the deliverable: `npm run media:optimize-image -- assets/hero/hero-leader-master.png public/media/future-commerce/hero-leader.webp 1280 88`. Confirm the printed size is <= 400 KB and dimensions are >= 1280x720. If it exceeds 400 KB, re-encode at a lower quality until it fits, but never below 82.
4. **Write the failing gate first.** Edit `scripts/release-audit.mjs`: delete lines 27–52 (the `heroVideoPath` read, the atom walk, the 1 MB budget and the faststart check) and replace with a hero-image check that reads `public/media/future-commerce/hero-leader.webp`, parses its WebP dimensions, and pushes a failure if the file is missing, `width < 1280`, `height < 720`, or size `> 400_000` bytes. Use `sharp` (already a dependency) via `await sharp(path).metadata()` and make the module top level `await`-capable, or parse the RIFF/VP8 header directly — either is acceptable as long as the check is real.
5. Run `npm run build && npm run audit:release`. It must now pass on the new asset. If you built step 3 correctly it passes; if it fails, fix the asset, not the threshold.
6. **Rewrite the e2e assertions before touching the component.** In `e2e/site-smoke.spec.ts` rewrite the six tests at lines 450, 493, 842, 861, 937 and 956 so that they assert:
   - `.commerce-hero-media img` exists, is visible, and its `src` contains `hero-leader.webp` (Next.js rewrites it through `/_next/image?url=...`, so assert with `toHaveAttribute("src", /hero-leader/)` or read `currentSrc` and match the substring — do **not** assert an exact `src`).

   - `.commerce-hero-media video` count is `0` at every tested width.
   - `.commerce-media-control` count is `0`.
   - the image `naturalWidth > 0` at 320 and 1440 (replaces the old 390/768/1280 poster loop at 956).
   - Delete the `is-ready`, `readyState`, `currentTime`, `duration >= 7.9`, `playbackRate` and `aria-label="Pause video"` assertions entirely.
   - Keep every non-hero assertion in those tests unchanged (the `figcaption` text checks, the `commerce-decision-layout` grid checks at 450, the copy/media bounding-box checks at 937).
7. Run `npm run test:e2e -- --grep "hero"` and confirm the rewritten tests FAIL against the current video component. That is the red step.
8. **Rewrite the component.** In `src/components/site/CommerceHeroMedia.tsx`:
