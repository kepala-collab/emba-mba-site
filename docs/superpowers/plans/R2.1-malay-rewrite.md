# R2.1 — Malay rewrite

## Goal

Rewrite the Malay site so it reads as native Kuala Lumpur copy in the register defined by `docs/superpowers/research/ms-register.md`, not as a translation of the English. One executor handles **one unit** from the table below per dispatch. Facts, numbers and controlled identifiers are imported constants and are never retyped.

## Model and role

- **Writer: Opus.** Rewrites the assigned unit.
- **Reviewer: Opus, separate agent, fresh context.** Runs section 7 of `ms-register.md` as a checklist plus the commands in Acceptance. Returns PASS, or FAIL with file:line references.
- **Loop limit: two.** Writer → reviewer → (fail) → writer → reviewer. A third failure stops the unit and escalates to the architect with the reviewer's last report. Do not attempt a third rewrite.

## Inputs — read these first, in full

1. `docs/superpowers/specs/2026-09-03-site-quality-programme-design.md` sections 2, R2.0, R2.1.
2. `docs/superpowers/research/ms-register.md` — **section 3 "Recommended register mix per page type"** (find your page type's row and obey its address form, sentence length, formality, CTA style and model sentence), **section 4 "Glossary EN → BM (site terms)"** (70 rows; Official entries are verbatim), **section 5 "Do / Don't"** (40 numbered rules), **section 6 "Audit of the current site Malay — 15 priority items"** (worked corrections — reuse them where they touch your unit), **section 7 "Self-validation checklist for a rewriting agent"** (20 checks; the reviewer runs all 20).
3. `SEO-CONTENT-GOVERNANCE.md` — the Clarity standard, Voice and tone, and Controlled terminology tables.
4. The English source of your unit, for meaning only: the `(en)` twin of your file path.
5. `src/lib/content.ts` — the constants you import. Never edit English strings here.

## Constraints

- **Facts are imported constants and are never retyped.** Every number, fee, duration, cohort id, date, module count and proper name comes from `FACTS`, `INTAKES`, `SITE`, `PROGRAMME_PROOF`, `HRD_CORP_CLAIM_MS`, `PROGRAMME_AUDIENCE_MS`, `REFUND_TERMS_MS`, `CTA_LABELS.ms` and their siblings. If you find yourself typing `RM10,000.00`, `6 bulan`, `12 modul` or `154` as a literal, you are doing it wrong — interpolate. The only exception is a string that is already a literal in the file you are editing and that `fact-parity.test.ts` locks.
- **Register rules, verbatim from spec section R2.1:** *Register per `ms-register.md` section 3. Key rules: official English terms kept in English in italics inside brackets on first use; HRD Corp and MQA verbs as the guide lists; `diiktiraf/diperakukan` for recognition, never `disokong`; RM with no space and comma thousands; Malay month names; `profesional yang bekerja` or `golongan pengurus dan eksekutif` instead of `pengurus bekerja` (this changes the Malay meta title and the Malay guide PDF title, so the PDF filename `panduan-pengurus-bekerja-2026.pdf` is kept as a stable URL but its displayed title changes in Release 3); CTA family `sesi perbincangan program`; warmth from `anda/kita/kami`, spoken connectives, long-then-short rhythm, no exclamation marks, no `-lah/nak/tak`.*
- **Headline limits:** Malay hero headline **<= 9 words**. Body sentence length per the section 3 row for your page type (hero 12–20 words; programme pages 15–25; fees 15–25 with one condition per sentence; FAQ answers 2–4 sentences of 12–22 words; insights 20–30; campaign 10–18).
- **Banned patterns.** `scripts/content-clarity-audit.mjs` gained a Malay list in R1.2 (`biasanya`, `disokong` near CMI, `projek aplikasi`, `pengurus bekerja`, `perbualan program`, `program awam`, `laluan lanjutan`). Your unit must produce **zero** hits under `node scripts/content-clarity-audit.mjs --strict-locales` for the file you touched.
- **Do not change positioning, claims or scope.** Same meaning, different Malay. If a sentence's English meaning is wrong, report it; do not fix it here.
- **Branch and release action.** One branch per unit: `feat/r2-1-malay-<unit-slug>`, e.g. `feat/r2-1-malay-fees` for unit 6. Pushing your feature branch to GitHub for CI is allowed. Merging into `codex/hostinger-deployment` and pushing that branch **is the deployment**; it happens only after the full section-6 gate is green for the whole release. Never do that from a unit.
- Hostinger configuration is out of scope for the whole programme.
- **Known blocker on unit 1.** `src/lib/__tests__/fact-parity.test.ts:49` asserts `PROGRAMME_POSITIONING_MS` contains `"dianugerahkan dan disokong oleh CMI"` — the exact phrase the register guide bans. Unit 1 must change that assertion to the new wording (`dianugerahkan dan diperakukan oleh CMI`) **in the same commit**, test first. No other unit may edit that test.

## Steps

**Writer**

1. Branch: `git checkout codex/hostinger-deployment && git checkout -b feat/r2-1-malay-<unit-slug>`.
2. Read the four Inputs. Then read your unit's file(s) in full and the `(en)` twin for meaning.
3. Identify your page type in `ms-register.md` section 3 and write down its address form, sentence length and CTA style before writing a word.
4. Rewrite. Metadata (`title`, `description`, OpenGraph) and every JSON-LD text field on the page are rewritten with the body — they are part of the unit.
5. Replace every literal fact with the imported constant. Add the import if it is missing.
6. Self-run `ms-register.md` section 7 checks 1–20 against your own output before handing over. Fix what you find.
7. `npm run lint && npm run typecheck && npm test && npm run audit:content && node scripts/content-clarity-audit.mjs --strict-locales` — the strict run must show zero hits **in your file** (hits in other files are other units' work).
8. Commit as `feat(ms): rewrite <unit name> in the Malay site register`. Hand to the reviewer with: the unit number, the branch name, the diff, and your section 7 self-check results.

**Reviewer (fresh Opus, no writer context)**

9. Read `ms-register.md` sections 3–7 and `SEO-CONTENT-GOVERNANCE.md`. Read the diff, not the conversation.
10. Run all 20 checks in section 7 against the changed file(s). Record each as pass or fail with a `file:line`.
11. Run the commands in Acceptance.
12. Grep the banned list explicitly: `perbualan program|Pengurus Bekerja|pengurus bekerja|projek aplikasi|laluan lanjutan|program awam|dan ke atas|dalam bentuk bertulis|dinilai untuk|disokong oleh CMI|atas talian|emel\b|kepemimpinan|biasanya|kebiasaannya|selalunya|kebanyakan` — expect zero in the changed files.
13. Verify every fact value against `content.ts` and confirm none was retyped as a literal.
14. Count words in every rewritten H1: hero H1 <= 9 words.
15. Return **PASS**, or **FAIL** with a numbered list of `file:line` + the failing section-7 check number + the required correction. Do not rewrite the copy yourself.

## Acceptance

Every command exits 0.

```
npm run lint
npm run typecheck
npm test
npm run audit:content
npm run audit:styles
npm run build
npm run audit:seo
npm run audit:release
npm run test:e2e
```

Plus:

- `node scripts/content-clarity-audit.mjs --strict-locales` reports **zero** Malay hits in the files this unit changed.
- All 20 `ms-register.md` section 7 checks pass, each recorded individually.
- Hero H1 <= 9 words; every other heading is a full noun phrase or a clause with a verb, sentence-case, no semicolon (section 7 check 15).
- Zero exclamation marks on programme, fees, FAQ and credential pages (check 14).
- `git diff` shows no change to any English or Chinese string.
