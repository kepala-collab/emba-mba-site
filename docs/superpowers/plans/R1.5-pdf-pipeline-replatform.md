# R1.5 — PDF pipeline re-platform (structure only)

## Goal

Replace the two overlapping Windows-only PDF generators with one deterministic, CI-runnable pipeline whose copy lives in per-language JSON so Release 3 can regenerate the twelve PDFs from final text. Output must be byte-identical across runs, Chinese glyphs must render from bundled OFL fonts, and page counts must not change.

## Model and role

Sonnet, single technical executor. No reviewer pass. This brief changes structure only — not one word of PDF copy.

## Inputs — read these first, in full

- `docs/superpowers/specs/2026-09-03-site-quality-programme-design.md` (section R1.5)
- `scripts/generate-lead-magnet-pdfs.py` (582 lines — read the whole thing; `DOCS` at line 168 is the document registry, `render()` at 141 is the page builder, `chrome()` at 68 is the page furniture)
- `scripts/generate-working-manager-guides.py` (314 lines)
- `scripts/render-lead-magnet-pdfs.py` (the proof renderer)
- `src/lib/lead-email.ts` lines 17–26 (`PROGRAMME_GUIDE_FILENAME`, `PROGRAMME_GUIDE_DELIVERED_NAME`) — the filenames these scripts must keep producing
- `src/lib/__tests__/fact-parity.test.ts` lines 53–66 — it greps every `.py` under `scripts/`
- `.github/workflows/quality.yml`
- `package.json`

## Constraints

- **Facts never change and copy never changes.** Every string moves from Python source into `scripts/pdf/copy/<lang>.json` **verbatim**. If a page currently reads `RM10,000.00`, the JSON reads `RM10,000.00`. Do not fix, tighten, translate or re-order any sentence. R3.2 rewrites the copy.
- **Filenames never change.** All twelve output filenames in `public/downloads/` stay exactly as they are, including `panduan-pengurus-bekerja-2026.pdf`.
- **Page counts never change**: 3 / 4 / 3 / 3 pages for the guide, decision guide, employer funding brief and scholarship eligibility documents respectively.
- **No `C:/Windows/Fonts`.** Any absolute Windows font path left anywhere is a failure.
- **`fact-parity.test.ts` scans your new Python.** The corpus must not contain `RM 4,000`, `RM 6,000`, `bertauliah MQA`, `Associate Partner` or `dianugerah dan disokong`. Note that `.json` is **not** in that test's extension filter, so the copy JSON is not scanned — do not rely on that as a licence to change copy.
- **Branch and release action.** Create `feat/r1-5-pdf-pipeline` from `codex/hostinger-deployment`. Pushing your feature branch to GitHub for CI is allowed and encouraged — this brief adds a CI step, so a real run is the best proof. Merging into `codex/hostinger-deployment` and pushing that branch **is the deployment**; it happens only after the full section-6 gate is green. Never do that from this brief.
- Hostinger configuration is out of scope for the whole programme.
- **Python invocation differs by environment.** Locally on this Windows machine the interpreter is the launcher: `py -3` (Python 3.14.7 is installed; `python` may not resolve in Git Bash). In CI it is `python3`, provided by `actions/setup-python`. The npm scripts must work in both — see step 9.
- **The nine `future-ready-*` PDFs are the approved follow-up library** named in `HANDOFF.md` and confirmed by the owner (spec assumption 3). Their existing text is the baseline for R3.2, not disposable draft material. Move it verbatim.
- The overlap is real: `generate-working-manager-guides.py` owns the three `*-2026` guides *and* declares ms/zh variants of the other three documents, which `generate-lead-magnet-pdfs.py` also owns. Last run wins today. Resolve the overlap by giving each of the four documents exactly one definition file.

## Steps

1. `git checkout codex/hostinger-deployment && git checkout -b feat/r1-5-pdf-pipeline`.
2. **Snapshot the baseline.** Record `sha256` and page count for all twelve files in `public/downloads/`. Keep this table; it is your regression oracle and part of the hand-back.
3. **Vendor the fonts.** Create `scripts/pdf/fonts/` and download the OFL-licensed families: Noto Serif (Regular, Bold), Noto Sans (Regular, Bold) and Noto Sans SC (Regular, Bold). Commit the `.ttf`/`.otf` files and the upstream `OFL.txt` alongside them. Add a one-line `scripts/pdf/fonts/README.md` naming each family, its version and its source URL.
4. **Dependencies.** Create `scripts/pdf/requirements.txt` pinning exact versions of `reportlab` and `pypdfium2`. Pin, do not range.
5. **Extract copy, mechanically.** Create `scripts/pdf/copy/en.json`, `scripts/pdf/copy/ms.json`, `scripts/pdf/copy/zh.json`. Move every user-visible string out of the two generators into these files, keyed by document id then by block. Suggested shape:
   ```json
   { "working-managers-guide": { "title": "...", "subtitle": "...", "blocks": [ {"kind": "para", "text": "..."}, {"kind": "table", "header": [...], "rows": [[...]]} ] } }
   ```
   The exact schema is yours, but it must be the same across the three languages and must round-trip every string that exists today. Copy strings with a script or careful cut-and-paste, never by retyping.
6. **Document definitions.** Create `scripts/pdf/documents/` with one module per document: `working_managers_guide.py`, `decision_guide.py`, `employer_funding_brief.py`, `scholarship_eligibility.py`. Each exports a `DOCUMENT` dict carrying the output filename per language and the ordered block structure, reading its text from the loaded copy JSON. No literal user-visible strings in these modules.
7. **One builder.** Create `scripts/pdf/build.py`: loads `copy/<lang>.json`, registers the bundled fonts (Noto Serif and Noto Sans for `en` and `ms`, Noto Sans SC for `zh`), reuses the existing page chrome (navy header bar, gold rule, footer) ported from `chrome()` in the old script, iterates the four documents across three languages, and writes to `public/downloads/`. Determinism requirements:
   - Set ReportLab `invariant=1` (via `reportlab.rl_config.invariant = 1` before building, or `SimpleDocTemplate(..., invariant=1)`).
   - Set fixed document metadata: fixed `title`, `author`, `subject`, `creator`, `producer`. No timestamps, no UUIDs, no `datetime.now()`.
   - Do not embed a build date anywhere in the PDF chrome unless the current PDFs already show one; if they do, move it to the copy JSON as a literal string.
8. **Verifier.** Create `scripts/pdf/check.py`: runs the build into a temporary directory, then asserts each generated file is byte-identical to the committed file in `public/downloads/` and that its page count matches the baseline. Exit non-zero on any mismatch, printing the filename and both hashes.
9. **npm scripts, cross-platform.** The local interpreter is `py -3`; the CI interpreter is `python3`. Do not hard-code either into the npm script. Add a tiny launcher `scripts/pdf/run.mjs` that spawns the first interpreter that answers `--version` from the ordered list `["python3", "py", "python"]` (passing `-3` when the binary is `py`) and forwards its argument as the script path, inheriting stdio and propagating the exit code. Then in `package.json`:
   ```json
   "pdfs:build": "node scripts/pdf/run.mjs scripts/pdf/build.py",
   "pdfs:check": "node scripts/pdf/run.mjs scripts/pdf/check.py"
   ```
   Verify both work locally, where `py -3` is the only interpreter on PATH in Git Bash.
10. **Regenerate and compare.** Run `npm run pdfs:build`. Diff each output against the baseline from step 2. Differences in *page geometry, glyph coverage or page count* are bugs to fix. Byte differences caused purely by the font switch (Arial/Georgia/SimHei → Noto) are expected — in that case, commit the regenerated PDFs and treat the **new** files as the baseline, then re-run `npm run pdfs:build` a second time and require `git diff --exit-code public/downloads` to be clean. Determinism is proven by the second run, not the first.
11. **Proof render.** Run `py -3 scripts/render-lead-magnet-pdfs.py` locally (adjust its input paths only if the filenames it expects moved — they should not). Install its dependency first if needed: `py -3 -m pip install -r scripts/pdf/requirements.txt`. Open the Chinese proof PNGs and confirm no tofu boxes, no clipped glyphs and no overflowing table cells. Do the same for the Malay and English proofs.
12. **Delete the old generators.** `git rm scripts/generate-lead-magnet-pdfs.py scripts/generate-working-manager-guides.py`. Keep `scripts/render-lead-magnet-pdfs.py`. Confirm zero references remain: `grep -rn "generate-lead-magnet\|generate-working-manager" . --exclude-dir=node_modules --exclude-dir=.git`.
13. **CI.** In `.github/workflows/quality.yml`, after the `npm ci` step add:
    ```yaml
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - run: python3 -m pip install -r scripts/pdf/requirements.txt
    ```
    and add `- run: npm run pdfs:check` as the final verification step, after `npm run test:e2e`. `actions/setup-python` puts `python3` on PATH, which `scripts/pdf/run.mjs` finds first.
14. Run the full gate (see Acceptance) plus `npm run release:sync && npm run release:check`, since `public/` changed.
15. Commit as: fonts + requirements; copy JSON extraction; builder + document modules + check; npm scripts + CI; removal of the old generators.

## Acceptance

Every command exits 0.

```
npm run lint
npm run typecheck
npm test
npm run audit:content
npm run audit:styles
npm run build
npm run audit:seo
npm run audit:release
npm run test:e2e
npm run pdfs:build
npm run pdfs:check
```

Plus, all required:

- `npm run pdfs:build && git diff --exit-code public/downloads` exits 0 — a second build produces byte-identical files.
- `ls public/downloads | wc -l` returns `12`, with the same twelve filenames as before.
- Page counts unchanged: 3, 4, 3, 3 for the four document families across all three languages.
- `grep -rn "C:/Windows" scripts/` returns nothing.
- Chinese proof PNGs render every glyph; state that you inspected them and what you saw.
- `npm run pdfs:check` exits 0 on a clean tree, resolving `py -3` locally through `scripts/pdf/run.mjs`.

## Out of scope

Any change to PDF copy, titles, section order or design (R3.2 owns copy; the Malay guide display-title change is R3.2's, not yours). Linking the nine unlinked PDFs into the site or the nurture emails (R3.1). Changing `PROGRAMME_GUIDE_FILENAME` or `PROGRAMME_GUIDE_DELIVERED_NAME` in `lead-email.ts`. Adding new documents.
