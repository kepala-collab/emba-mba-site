# R3.1 — Email flow

## Goal

Rewrite the four-email sequence in all three languages from the final Release 2 copy, link the nine `future-ready-*` PDFs that are currently linked from nothing into the nurture steps, and add one retry to the nurture sender so a transient SMTP failure does not silently drop a step.

## Model and role

- **Sonnet** for the schema migration, the retry logic and the tests.
- **Opus writer + separate Opus reviewer** for the email copy in each language, one language per dispatch, using the *Acknowledgement and nurture e-mails* row of section 3 of the matching register guide. Loop limit two per language.

## Constraints

- **Facts never change and are never retyped.** `FACTS`, `INTAKES` and the locale constants are interpolated. The email register rows in the guides are the voice; the constants are the content.
- **Filenames never change.** Every link points at an existing file in `public/downloads/`. Verify each path resolves before committing.
- **Mechanics of the day-0 acknowledgement are unchanged**: same trigger, same attachment behaviour, same `Auto-Submitted: auto-replied` and `X-Auto-Response-Suppress: All` headers, no `List-Unsubscribe` on the ack. Only the copy changes.
- **Nurture mail carries links, not attachments.** Do not add an attachment to any of the three nurture steps.
- **Keep the 45-day cutoff** (`MAX_LEAD_AGE_DAYS`).
- **Migration 010 must be non-destructive**: it adds one nullable column with a default. Rollback is redeploying the previous archive, so the schema must remain compatible with the previous code.
- **Branch and release action.** Create `feat/r3-1-email-flow` from `codex/hostinger-deployment`. Pushing the feature branch for CI is allowed. Merging into `codex/hostinger-deployment` and pushing that branch **is the deployment**; only after the section-6 gate is green.
- Hostinger configuration is out of scope. `UNSUBSCRIBE_TOKEN_SECRET` and `NURTURE_CRON_SECRET` are assumed configured; this brief **verifies the nurture cron responds** before relying on it, but never sets a secret.
- **Real sends go to the operator mailbox only.** One per language, three total. Never send to a real lead address, never bulk-send, never send from a test loop.

## Steps

1. `git checkout codex/hostinger-deployment && git checkout -b feat/r3-1-email-flow`.
2. **Confirm the inputs are final.** `git log --oneline` must show the R2 copy merged. If `content-ms.ts` or `content-zh.ts` still carries pre-R2 wording, stop — this brief rewrites *from* final copy.
3. **Map the sequence before writing.** Record the target for each step:
   | Step | Delay | Link target | Attachment |
   |---|---|---|---|
   | Ack | day 0 | — | programme guide by language (unchanged) |
   | day3 | 3 days | `/downloads/future-ready-decision-guide[-ms\|-zh].pdf` | none |
   | day7 | 7 days | `/downloads/future-ready-employer-funding-brief[-ms\|-zh].pdf` **and** the cohort view (`/intakes`, `/ms/intakes`, `/zh/intakes`) | none |
   | day14 | 14 days | `/downloads/future-ready-scholarship-eligibility[-ms\|-zh].pdf` **and** the no-commitment conversation (`/apply`, `/ms/apply`, `/zh/apply`) | none |
   Verify all nine PDF paths exist on disk.
4. **Extend `StepCopy` — test first.** In `src/lib/__tests__/nurture-email.test.ts` add assertions, for each of the three languages and three steps:
   - The rendered HTML contains the exact PDF href for that step and language.
   - day7 and day14 each contain **two** distinct links (the PDF and the page), and day3 contains the decision-guide PDF link.
   - Every link carries the existing UTM query (`utm_source=nurture&utm_medium=email&utm_campaign=<step>&utm_content=<language>`), including the new PDF links.
   - Every rendered email contains a `List-Unsubscribe` one-click URL and a plain-text part.
   - No nurture step has an attachment.
5. `npm test` — red. Add a `resourceHref` (or `resources: {label, path}[]`) field to `StepCopy`, populate it for all nine step/language combinations, and render it in `renderNurtureEmail` through the same UTM builder used at line 240. `npm test` — green.
6. **Migration 010.** Create `database/migrations/010_add_nurture_attempt_count.sql`: `ALTER TABLE lead_nurture_log ADD COLUMN attempt_count TINYINT UNSIGNED NOT NULL DEFAULT 0;` Nothing else in this file.
7. **Retry logic — test first.** Add unit coverage asserting: a nurture send that fails increments `attempt_count` and stays claimable; a second attempt is only eligible **60 minutes** after the first; after the second failure the row is terminal (`message_id` = `send_failed`, as today); a row older than `MAX_LEAD_AGE_DAYS` is never retried. Then implement in the nurture sender. Keep the "latest step first, earlier overdue steps marked superseded" behaviour unchanged.
8. **Copy rewrite — one language per dispatch.** Opus writer:
   - Read the guide's section 3 e-mail row and section 5, then the current `EN`/`ZH`/`MS` block.
   - Rewrite `subject`, `preheader`, `greeting`, `headline`, `paragraphs`, `facts`, `ctaLabel`, `secondaryLabel` and the `FOOTER` block for that language.
   - Malay: greeting `Salam sejahtera, {Nama},` with fallback `Tuan/Puan` (never `anda`); sign-off `Salam hormat, Pasukan Program Future Ready Executive MBA`. Clear the section 7 check 6 banned list — `perbualan program`, `projek aplikasi`, `biasanya`, `kalendar langsung`, `masih tinggal`, `jujur` predicated of a guide.
   - Chinese: greeting `{姓名}，您好：`, sign-off `课程团队 敬上`. Clear `诚实边界`, `日历`, `宣传册`, `班次`, `获取`, `营销`.
   - English: apply the R2.3 clarity rules and align the CTA family.
   - Facts are interpolated constants.
   Opus reviewer, fresh context, runs section 7 of the matching guide plus the Acceptance commands, and returns PASS or FAIL with line references. Two loops maximum.
9. **Acknowledgement email.** Rewrite the three `buildApplicationReceivedEmail` copy blocks in `lead-email.ts` the same way, same writer/reviewer loop. Confirm the attachment filenames and delivered names at lines 17–27 are untouched.
10. **Dry run.** `POST /api/internal/nurture` with `NURTURE_CRON_SECRET` and `{"dryRun": true, "limit": 5}` against staging data. Confirm it responds, selects the expected rows, and renders each without error. This also satisfies the spec's requirement to verify the cron responds before relying on it.
11. **One real send per language** to the operator mailbox. For each of `en`, `zh`, `ms` check: subject line, attachment name (ack only), every link resolves and carries its UTM, the `List-Unsubscribe` header and one-click POST work, and a plain-text part is present and readable.
12. Run the full gate (see Acceptance). Commit as: migration; retry logic + tests; nurture link structure + tests; one copy commit per language; ack copy.
