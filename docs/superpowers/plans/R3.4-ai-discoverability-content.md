# R3.4 — AI discoverability content

## Goal

R1.4 built `llms.txt` and `llms-full.txt` with placeholder-neutral English descriptions. Refresh both from the final Release 2 copy in all three languages, and make the positioning sentence and interpretation bullets come from **one** shared source function that `chat-knowledge.ts` also uses — so the assistant and the machine-readable files can never drift apart.

## Model and role

- **Sonnet** for the refactor, the shared function and the tests.
- **Opus writer + separate Opus reviewer** for the Malay and Chinese descriptions and interpretation bullets, one language per dispatch. Loop limit two. English is a Sonnet pass against `SEO-CONTENT-GOVERNANCE.md`.

## Inputs — read these first, in full

- `docs/superpowers/specs/2026-09-03-site-quality-programme-design.md` (section R3.4, and section 1 item 6)
- `src/app/llms.txt/route.ts` — as R1.4 left it
- `src/app/llms-full.txt/route.ts` — as R1.4 created it
- `src/lib/chat-knowledge.ts` — the fact source function R1.4 extracted (`verifiedProgrammeFacts`) and the Malay block R2.4 added
- `src/lib/locale-routes.ts` — `EN_ROUTES`, `LOCALE_PAIRS`, and `NOINDEX_ROUTES` if R3.3 exported it
- `src/lib/content.ts`, `content-ms.ts`, `content-zh.ts` — the merged Release 2 copy
- `docs/superpowers/research/ms-register.md` sections 3, 5, 7
- `docs/superpowers/research/zh-register.md` sections 3, 5, 7
- `SEO-CONTENT-GOVERNANCE.md`

## Constraints

- **Facts never change and are never retyped.** Every fact in either file interpolates a constant.
- **One source, two consumers.** After this brief, the positioning sentence and the interpretation bullets must exist in exactly one function. `chat-knowledge.ts`, `llms.txt` and `llms-full.txt` all call it. A grep for a duplicated interpretation bullet must return one definition.
- **These files are read by machines that will quote them.** Every sentence must be defensible on its own, outside page context. No urgency, no prestige labels, no unqualified claims, and every conditional outcome names its decision-maker.
- **Register applies here too.** The Malay and Chinese descriptions are copy and go through the writer/reviewer loop like any page.
- **Branch and release action.** One branch per unit: `feat/r3-4-llms-<unit>`. Pushing feature branches for CI is allowed. Merging into `codex/hostinger-deployment` and pushing that branch **is the deployment**; only after the section-6 gate is green.
- Hostinger configuration is out of scope.
- Run this brief **last in Release 3**, after R3.1, R3.2 and R3.3 have merged — it quotes the final state of everything else.

## Steps

**Unit 1 — the shared source**

1. `git checkout codex/hostinger-deployment && git checkout -b feat/r3-4-llms-shared`.
2. **Write the failing test first.** Add to `src/lib/__tests__/chat-knowledge.test.ts`:
   - `interpretationBullets("en")` returns a non-empty array of strings, and every one of them appears verbatim in the body returned by `llms.txt`'s `GET()`.
   - The same for `"ms"` and `"zh"` against `llms-full.txt`'s `GET()`.
   - `programmePositioning("en") === PROGRAMME_POSITIONING_SENTENCE`, `programmePositioning("ms") === PROGRAMME_POSITIONING_MS`, `programmePositioning("zh") === PROGRAMME_POSITIONING_ZH`.
   - `programmeChatSystemPrompt(lang)` contains `programmePositioning(lang)` for all three languages.
   This test is the anti-drift mechanism: it fails the moment a bullet is edited in one place and not the other.
3. `npm test` — red. In `src/lib/chat-knowledge.ts` export `programmePositioning(language: ChatLanguage): string` and `interpretationBullets(language: ChatLanguage): string[]`. Populate the bullet arrays from the existing `## Important interpretation` block in `llms.txt` (English) and from the merged `content-ms.ts` / `content-zh.ts` constants for the other two. Have `programmeChatSystemPrompt` and both routes consume them.
4. `npm test` — green. Commit as `refactor(chat): share the positioning sentence and interpretation bullets`.

**Units 2–4 — the text**

5. Branch from `codex/hostinger-deployment` after the previous unit has merged.
6. Rewrite your language's sections in both routes:
   - `llms.txt`: the site header line, the positioning paragraph, the provider/operator separation sentence, every **Primary sources** description (one terse clause per link, in that language), and the **Contact** labels. The route lists themselves stay derived from `EN_ROUTES`/`LOCALE_PAIRS` — do not hand-write a URL.
   - `llms-full.txt`: your language's section, with the fact bullets rendered from constants and the interpretation bullets from unit 1's function.
7. Malay writer: apply `ms-register.md` section 3 — this is closest to the **PDF guides** register (document voice, roles plus `anda`, official identifiers in English). Chinese writer: `zh-register.md` section 3, decoration score **1** — this is a reference document, not marketing; `您` throughout, full-width punctuation, `索取` not `获取`.
8. Reviewer, fresh Opus: run section 7 of the matching guide against the changed strings; run the Acceptance commands; verify every fact is interpolated; return PASS or FAIL with line references. Two loops maximum.
9. Commit as `feat(llms): refresh the <language> text from the final copy`.
