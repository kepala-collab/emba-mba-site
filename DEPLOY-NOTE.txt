ONE-TIME SETUP REQUIRED AFTER DEPLOY
-------------------------------------------------------------------------
1. Run the migration ONCE against the Hostinger MySQL database:
     database/migrations/008_add_marketing_optout_and_nurture_log.sql
   (adds leads.marketing_opt_out + marketing_opt_out_at, creates lead_nurture_log)

2. Add two new environment variables (each a random string, 32+ characters):
     UNSUBSCRIBE_TOKEN_SECRET=<random 32+ chars>   # signs unsubscribe links
     NURTURE_CRON_SECRET=<random 32+ chars>        # protects the cron endpoint
   Generate with:  openssl rand -hex 32

3. Add a daily cron job in Hostinger (any time of day, once per day):
     curl -X POST "https://futurereadymba.com/api/internal/nurture" \
          -H "Authorization: Bearer $NURTURE_CRON_SECRET"

4. Test safely first — dry run sends nothing, just reports who WOULD get what:
     curl "https://futurereadymba.com/api/internal/nurture?dryRun=1" \
          -H "Authorization: Bearer $NURTURE_CRON_SECRET"

Notes:

  - If the secrets are missing the endpoints refuse politely (503) — nothing breaks.
